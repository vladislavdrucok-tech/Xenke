# Deep Bounce 1.1 — монетизація: Google Play Billing, AdMob, UMP

Цей документ — для власника гри: що реалізовано, як налаштувати Play Console і AdMob, що заповнити в
Data safety, як перевірити покупки з тестерами ліцензій і що саме не вдалося перевірити в моєму середовищі.

Усі ідентифікатори та налаштування реклами/покупок зібрані в одному файлі: **`config/monetization.cfg`**.
Ключ підпису APK/AAB і паролі в репозиторій не потрапляють (див. README → «Ключ підпису»).

## 2. Налаштування Play Console (крок за кроком)

1. **Застосунок:** пакет `com.deepbounce.game` (вже в `export_presets.cfg`). Зберіть підписаний AAB:
   `tools/android/build_release.sh aab` (ключ — зі змінних середовища, див. README).
2. **Завантажте AAB у «Внутрішнє тестування»** (Testing → Internal testing → Create release). Без завантаженої
   збірки з бібліотекою Billing сторінка товарів не відкривається. Додайте себе в список тестерів, відкрийте
   посилання для участі й встановіть гру з Play на телефон.
3. **Товари:** Monetize with Play → Products → One-time products → Create one-time product — для кожного ID з
   таблиці: Product ID (точно як у таблиці), назва й опис (англійська за замовчуванням + переклади з
   `docs/PLAY_PRODUCTS.md`), Purchase option «Buy», ціна в USD → «Set prices» (Google перерахує в місцеві
   валюти), **Activate**. Для витратних товарів окремого прапорця немає: «витратність» робить код гри (consume).
4. **Ключ ліцензування:** Monetize with Play → Monetization setup → Licensing → скопіюйте Base64 public key у
   `config/monetization.cfg`, `[billing] license_key="…"`. Тоді кожен підпис покупки (`originalJson` +
   `signature`) перевіряється на пристрої RSA‑SHA256; без ключа гра пише попередження в лог і довіряє стану
   покупки з Play Billing Library.
5. **Тестери ліцензій:** Settings (налаштування акаунта розробника) → License testing → додайте свій Gmail
   (той самий, що на телефоні). Для них у вікні оплати з'являються тестові картки: «Test card, always approves»,
   «… always declines», «Slow test card, approves after a few minutes» (перевірка PENDING), «… declines after a few
   minutes». Гроші не списуються.
6. **Повернення коштів (refund):** Order management → знайти тестове замовлення → Refund → обов'язково
   **Revoke entitlement**. Після наступного запуску гри (або «Відновити покупки») право зникне.
7. **Реклама в лістингу:** App content → Ads → «Yes, my app contains ads».
8. **Цільова аудиторія:** App content → Target audience — рекомендовано 13+ (або 16+). Якщо обрати дітей, то
   реклама повинна бути child-directed (потрібні інші налаштування AdMob) — у поточній конфігурації не обирайте.
9. **Політика конфіденційності:** обов'язкова для гри з рекламою — розмістіть сторінку на своєму домені й
   укажіть URL у Store settings та в AdMob (Privacy & messaging).

## 3. Налаштування AdMob

1. AdMob → Apps → Add app → Android → (після публікації — прив'язати до лістингу Play). Скопіюйте **App ID**
   (`ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY`).
2. Створіть **три** рекламні блоки (Ad units):
   - Rewarded «Deep Bounce — Continue» (друга спроба),
   - Rewarded «Deep Bounce — Double crystals»,
   - Interstitial «Deep Bounce — Between runs».
   Нагорода в налаштуваннях блоку не важлива (гра сама визначає, що дає перегляд).
3. Впишіть у `config/monetization.cfg`:
   ```ini
   [admob]
   use_test_ads=false
   real_app_id="ca-app-pub-…~…"
   real_rewarded_revive="ca-app-pub-…/…"
   real_rewarded_double="ca-app-pub-…/…"
   real_interstitial="ca-app-pub-…/…"
   ```
   App ID плагін експорту сам вставляє в AndroidManifest (`com.google.android.gms.ads.APPLICATION_ID`). Поки
   `use_test_ads=true` або реальні ID порожні, гра використовує **офіційні тестові блоки Google** — так зібрані
   APK/AAB у цій поставці (у лозі експорту є попередження про тестовий App ID у release).
4. **Тестові пристрої:** при першому запуску SDK пише в logcat `Use RequestConfiguration.Builder().setTestDeviceIds(...)`
   з хешем пристрою — впишіть його в `test_device_ids`, щоб на своєму телефоні бачити тестову рекламу і з
   реальними блоками (власні кліки по реальній рекламі заборонені правилами AdMob).
5. **Privacy & messaging (UMP):** AdMob → Privacy & messaging → створіть і опублікуйте повідомлення «European
   regulations» (GDPR, ЄЕЗ + Велика Британія + Швейцарія) і, за бажанням, «US state regulations». Вкажіть URL
   політики конфіденційності. Без опублікованого повідомлення форма згоди не показується.
6. **app-ads.txt:** у Play Console вкажіть сайт розробника (Store settings → Website). На корені цього домену
   розмістіть файл `https://<ваш-домен>/app-ads.txt` з рядком (pub-ID — з AdMob → Settings → Account information):
   ```
   google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0
   ```
   AdMob перевіряє файл до 24 годин; без нього частина рекламодавців не купує показ.
7. `max_ad_content_rating="PG"` у конфігурації — відповідає рейтингу гри; змініть, якщо рейтинг інший.

## 4. Як працює реклама в грі

- **UMP:** при кожному запуску `requestConsentInfoUpdate` → якщо потрібно, форма згоди → тільки коли
  `canRequestAds() == true` SDK ініціалізується, і перед **кожним** запитом реклами це перевіряється знову.
  Якщо країна вимагає (ЄЕЗ), у «Налаштуваннях» з'являється кнопка «Налаштування конфіденційності»
  (`showPrivacyOptionsForm`). Власник «Без реклами» SDK взагалі не запускає.
- **Друга спроба (rewarded):** камінь перетнув червону лінію → гра зупиняється й зберігається → вибір
  «Продовжити за відео» / «Завершити забіг»; кнопка відео активна лише коли відео завантажене (інакше
  «Завантажуємо відео…» або «Відео недоступне» + «Повторити»). Коли SDK підтверджує нагороду
  (`onUserEarnedReward`), нагорода спершу записується в журнал («earned»), потім застосовується: кульки в гарматі,
  стан прицілювання, видаляються цілі камені, чий колайдер вище лінії або менш ніж на 2 висоти клітинки нижче
  (причина «revive», без кристалів), і «друга спроба використана» + «нагороду застосовано» пишуться одним
  збереженням. Раз за забіг/спробу; наступне перетинання — одразу результати. Закрив відео раніше / помилка
  показу — повернення до того самого вибору.
- **Подвоєння кристалів (rewarded):** на екрані результатів кристали забігу вже зараховані; відео додає ту саму
  суму ще раз, один раз на унікальний ID забігу/спроби (журнал «double:<id>»: earned → applied). Повторний
  callback, повторне натискання, перезапуск між нагородою й зарахуванням — сума не дублюється й не губиться.
  Для рівнів подвоюється разом із бонусом першого проходження.
- **Interstitial:** лише безкоштовна версія, лише після «Ще забіг» / «Наступний рівень» / «Повторити».
  Перші 3 завершені забіги/спроби — без реклами; далі ≥ 3 завершені забіги **і** ≥ 180 с активної гри від
  попереднього показу; не після забігу, де дивилися rewarded-відео. Не завантажилось — гра стартує одразу.
  Під час будь-якої повноекранної реклами гра стоїть на паузі, звук вимкнено. Усі ці числа — у
  `config/monetization.cfg` → `[ads_caps]`.
- **«Без реклами» з екрана поразки:** посилання «Прибрати рекламу» на екрані другої спроби → лист із точним
  переліком, що входить і що ні → покупка → назад на той самий вибір із тим самим забігом, тепер кнопка
  «Продовжити» без відео.

## 5. Покупки: цілісність і спосіб перевірки

| Ситуація | Що робить гра |
|---|---|
| `PURCHASED` | право й запис у журналі токенів (`purchaseToken → стан`) одним збереженням; потім acknowledge (постійні) або consume (витратні) |
| `PENDING` | нічого не видає, кнопка «Очікуємо оплату…», повідомлення; при поверненні в гру (`onResume`) — повторний `queryPurchases`; оплата пройшла → видача; скасована → запис «cancelled» |
| Подвійне натискання | одна покупка на товар одночасно (`busy`), друге вікно Play не відкривається |
| Скасування в Play | «cancelled», нічого не видано |
| Розрив з'єднання / немає мережі | помилка ≠ відсутність покупки: права не забираються; повторне підключення при поверненні |
| Перезапуск процесу | на старті `queryPurchases`: видача незавершених, повторний acknowledge/consume, якщо попередній не вдався |
| Повторна доставка того самого токена | журнал токенів: видача рівно один раз |
| Повернення коштів | якщо Google Play **відповів успішно** і постійного товару більше немає — право знімається (вибране оздоблення → класичне) |
| «Відновити покупки» | у Магазині й у Налаштуваннях: `queryPurchases` і синхронізація постійних прав |

**Спосіб перевірки покупки (точно):** гра офлайнова й без сервера, тому перевірка — на пристрої:
(1) стан `PURCHASED` від Play Billing Library 9.1 (плагін GodotGooglePlayBilling 3.3.0); (2) `packageName ==
com.deepbounce.game`; (3) якщо задано `license_key` — криптографічна перевірка підпису `originalJson`
ключем ліцензування (RSA, SHA256withRSA, `Crypto.verify`), інакше видачі немає; (4) ідемпотентний журнал
`purchaseToken`. Серверної перевірки через Google Play Developer API немає — на рутованому пристрої таку
перевірку теоретично можна обійти; для офлайн-гри з косметикою це звичайний компроміс. Якщо в майбутньому
з'явиться сервер — додати перевірку токена через `purchases.products.get`.

## 6. Data safety (Play Console → App content → Data safety)

Гра сама нічого не збирає й не передає: прогрес, налаштування й журнал покупок — лише у файлі на пристрої
(`user://deep_bounce.save`). Дані збирають SDK Google:

| Категорія Data safety | Тип | Хто | Навіщо | Обов'язково? |
|---|---|---|---|---|
| Device or other IDs | Advertising ID (AD_ID), App set ID | Google Mobile Ads SDK | Advertising or marketing, Analytics, Fraud prevention | так (для безкоштовної версії) |
| Location | Approximate location (з IP) | Google Mobile Ads SDK | Advertising, Fraud prevention | так |
| App activity | App interactions (покази/кліки реклами) | Google Mobile Ads SDK | Advertising, Analytics | так |
| App info and performance | Crash logs, Diagnostics | Google Mobile Ads SDK | Analytics, Fraud prevention | так |
| Financial info → Purchase history | обробляє Google Play (не розробник) | Google Play Billing | покупки | — (Google Play сам по собі; зазвичай не декларується розробником) |

Відповіді форми: дані передаються третій стороні (Google) — **так**; шифрування під час передачі — **так**;
дані збираються — **так** (рекламним SDK); користувач може відмовитись — частково (згода UMP у ЄЕЗ, скидання
рекламного ID в Android); запит на видалення — локальні дані видаляються разом із грою.
Дозволи APK: `INTERNET`, `ACCESS_NETWORK_STATE`, `com.google.android.gms.permission.AD_ID`,
`com.android.vending.BILLING`, `VIBRATE`. Офіційні підказки Google для Data safety щодо AdMob:
https://developers.google.com/admob/android/privacy/play-data-disclosure

## 7. Перевірка з тестерами ліцензій (що зробити на своєму телефоні)

У моєму середовищі це неможливо (див. «Блокери»), тому — короткий план для власника після кроків 2–5 розділу 2:

1. Встановити гру з внутрішнього тестування (не з APK — інакше Google Play не пов'яже покупку з грою).
2. Магазин → Кульки → «Бурштин» → «Купити · ціна» — ціна у вашій валюті; оплатити «always approves» → кульки
   видані й обрані; «Купити» більше немає.
3. «Морозна перлина» → «Slow test card…» → «Очікуємо оплату…»; згорнути гру на кілька хвилин, повернутись → видано.
4. «Підтримка автора» → «Мала» → подяка; купити ще раз — працює (consume).
5. «Без реклами» з екрана другої спроби (дійти до червоної лінії) → забіг збережено, «Продовжити» без відео.
6. Видалити гру, встановити знову → Налаштування → «Відновити покупки» → усе постійне повернулось.
7. Play Console → refund + revoke для «Бурштину» → у грі «Відновити покупки» → право зникло.
8. Реклама: з `use_test_ads=true` мають показуватись тестові відео з написом «Test Ad»; у ЄЕЗ (або з
   `debug_geography_eea=true` і своїм test device ID) — форма згоди UMP і кнопка конфіденційності в налаштуваннях.
